# Mobile-only web music player — архитектура прототипа

Горизонт: 2 дня. Цель — потрогать взаимодействие и анимации, а не построить продукт.
Оптимизируем скорость сборки и качество ощущений, а не масштабируемость.

## 0. Допущения

- Только мобильный веб. Десктоп не поддерживаем (показываем заглушку или просто верстаем в 430px по центру).
- Треки — статические mp3 в `/public/tracks/`, метаданные — `tracks.json`. Бэкенда нет.
- Один пользователь, без авторизации. Состояние — в памяти + `localStorage`.
- Онлайн-режим. Офлайн/кеширование — вне скоупа.

## 1. Стек

| Слой | Выбор | Почему |
|---|---|---|
| Сборка | Vite + TypeScript | мгновенный dev-сервер, ноль конфига |
| UI | React 19 | привычно, много готового |
| Стили | Tailwind CSS v4 | скорость; токены живут в CSS-переменных |
| Состояние | Zustand | 1 файл стора, без провайдеров и boilerplate |
| Анимации | Motion (framer-motion) | `layoutId` + `drag` — ключ ко всей механике плеера |
| Микро-анимации | Rive (опционально) | play/pause morph, эквалайзер — если останется время |
| Роутинг | без библиотеки | 3 экрана, хватит стейта `activeTab` |
| Деплой | Vercel | `git push` → превью-ссылка на телефон |

Осознанно **не берём**: Next.js (SSR не нужен, добавляет трение), Redux, react-router, UI-киты.

## 2. Ключевое архитектурное решение: аудио вне React

`HTMLAudioElement` — это императивный объект с собственным жизненным циклом. Если рендерить
его как JSX и управлять пропсами, React будет пересоздавать/перематывать его на ре-рендерах,
а на iOS это ломает автоплей. Поэтому:

```
audio/engine.ts   ← singleton, создаётся один раз при импорте модуля
                    new Audio(), подписки на timeupdate/ended/error
                    экспортирует императивный API: load/play/pause/seek
```

React только **отдаёт команды** движку и **подписывается** на его события. Движок — источник
правды о фактическом состоянии воспроизведения; стор — о намерении пользователя (что играем,
очередь, режимы).

### Частота обновлений

Позиция трека меняется ~4 раза в секунду (`timeupdate`), а при скрабе — на каждый `pointermove`.
Класть её в глобальный стор нельзя — перерисуется всё дерево.

```
progress: отдельная подписка → useSyncExternalStore → читает только <ProgressBar> и таймеры
playback: zustand → track, queue, isPlaying, shuffle, repeat
```

Два независимых канала. Список треков не перерисовывается при движении прогресс-бара.

## 4. Модель данных

```ts
type Track = {
  id: string
  title: string
  artist: string
  album?: string
  duration: number      // секунды, из манифеста — не ждём метаданных аудио
  src: string           // /tracks/xxx.mp3
  artwork: string       // /art/xxx.jpg
  color: string         // доминантный цвет обложки, hex — захардкожен в манифесте
}

type PlayerState = {
  queue: Track[]        // то, что реально играет по порядку
  index: number
  isPlaying: boolean
  shuffle: boolean
  repeat: 'off' | 'all' | 'one'
}
```

`duration` и `color` кладём в манифест руками. Считать длительность из файла и извлекать цвет
через canvas — это полдня работы ради данных, которых всего 15 строк.

## 5. Механика экранов

Три состояния плеера, одна анимация между ними:

```
[ скрыт ]  →  [ мини-плеер: 64px над таб-баром ]  →  [ полноэкранный ]
                        ↑ swipe up / tap ↓ swipe down
```

Переход мини → фулл делается через `layoutId` на обложке, названии и кнопке play:
Motion сам интерполирует позицию и размер. Это даёт «раскрывающийся» переход как в Apple Music
без ручной анимации координат.

Свайп — `drag="y"` с `dragConstraints` и `onDragEnd`, порог по velocity, а не только по смещению
(иначе быстрый короткий свайп не срабатывает и ощущается тупым).

Табы: Library / Search. Now Playing — не таб, а оверлей поверх всего.

## 6. Специфика мобильного веба (то, что съест время, если не заложить)

| Проблема | Решение |
|---|---|
| `100vh` больше экрана из-за адресной строки | `100dvh`, фиксированный `Shell`, скроллится только контент |
| Вырез и home indicator | `viewport-fit=cover` + `env(safe-area-inset-*)` в паддингах Shell |
| iOS блокирует автоплей | первый `play()` строго внутри обработчика тапа; `unlock.ts` на первом касании |
| Громкость на iOS не управляется из JS | не рисуем слайдер громкости вообще |
| Локскрин и наушники | `navigator.mediaSession` — metadata + handlers play/pause/next/prev |
| Двойной тап зумит | `touch-action: manipulation`, `user-scalable=no` |
| Серая подсветка при тапе | `-webkit-tap-highlight-color: transparent`, свои `:active` состояния |
| Скролл «протекает» под оверлей | `overscroll-behavior: contain` на скролл-контейнерах |
| Фоновое воспроизведение | работает нестабильно во вкладке; PWA-манифест + `display: standalone` заметно улучшает |

## 8. Что осознанно не делаем

Авторизацию, бэкенд, офлайн/Service Worker, плейлисты и лайки с персистом,
визуализацию спектра (Web Audio API — отдельный слой сложности и ломает MediaSession-сценарии),
тесты, десктопную адаптацию, i18n.

## 9. Точки роста, если прототип понравится

- Замена `data/tracks.ts` на API-клиент — остальной код не меняется, это и есть смысл слоя.
- Web Audio API поверх `engine.ts` для кроссфейда и анализа спектра.
- Service Worker + Cache API для офлайна.
- Rive-анимации вместо статичных иконок.
